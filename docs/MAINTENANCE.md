# 维护与发布

0.2.x 是预发布线，目标是先稳定导入、输入和保存。main 的 push / PR 会运行回归检查与 release 构建。只发布 CI 通过且真机检查过的提交。

每次发布：

1. 明确本次行为变化、迁移影响和剩余限制，更新 CHANGELOG 与 VALIDATION。
2. 修改 prepare_build.py 的 versionName / versionCode 和应用关于文字，保证 versionCode 递增。
3. 验证 ZIP 错误回滚、已有游戏不被覆盖、图标启动、按键、保存、退出环境、重启 LOAD。
4. 使用已保管的同一签名证书生成 release APK，验证签名和 SHA-256。
5. 创建版本 tag，将签名 APK、SHA256SUMS 和对应源码放到 GitHub Release。标明预发布或稳定版及实测设备。
6. 更新兼容性问题，保持未验证事项清楚可见；不要用新的功能掩盖存档回归。

当前首个公开版本保留开发期安装的证书，以便现有平板覆盖升级。该证书未进入仓库；未来更新需要维护者继续保管同一私钥。CI 没有签名凭据，自动构建仅供审核。

## 近期路线

- 扩充不同引擎、GPU 和设备的兼容性矩阵。
- 同场景帧时间与音频、触控延迟的测量，而非只有标题 FPS。
- 完整游戏库与任意自定义存档位置的跨设备迁移。
- 持久化导入任务、进度与取消恢复，处理 Android 因内存压力结束进程。
- 将运行环境的固定包名路径迁移，支持与官方 Winlator 共存。
- 补全上游预编译组件的完整对应源码与构建材料索引。

问题由 bug 和兼容性模板收集。后续维护依赖维护者处理 issue 和发布版本，项目没有后台更新、自动拉取游戏或监控用户文件的服务。
